# 用語集

このプロジェクトで出てくる言葉の説明です。五十音・アルファベット順ではなく、分野ごとに並べています。

## 全体
| 用語 | 説明 |
|---|---|
| API | プログラム同士がやりとりするための窓口。このツールでは「画面 ↔ サーバー」「フォーム ↔ サーバー」をHTTPでつなぐ |
| フロントエンド | ブラウザで動く画面側のプログラム（`frontend/`） |
| バックエンド | サーバーで動くプログラム（`backend/`）。データの保存や業務ルールの処理をする |
| モノレポ | 画面・サーバー・インフラなど複数のプログラムを1つのリポジトリで管理する方式 |
| CI | 継続的インテグレーション。プッシュのたびに自動でビルド・テストを行い、壊れていないか確かめる仕組み。ここでは GitHub Actions を使う |
| GitHub Codespaces | GitHubが用意するクラウド上の開発環境。ブラウザだけで、Java・Node.jsが入った環境でコードを動かせる。設定は `.devcontainer/devcontainer.json` |
| dev container（開発コンテナ） | 開発環境の中身（入れる道具、開くポートなど）を `devcontainer.json` に書いておき、誰でも同じ環境を作れるようにする仕組み |
| ポート / ポート転送 | ポートは1台のコンピューターの中でプログラムを区別する番号（画面は5173、APIは8080）。ポート転送は、Codespaces の中のポートを自分のブラウザから開けるようにすること |
| インメモリ | データをデータベースではなくプログラムのメモリに置くこと。速くて準備がいらないが、止めると消える。試作版はこれで動かしている |
| 改行コード（LF / CRLF） | 行の終わりを表す見えない文字。Mac・Linux は LF、Windows は CRLF を使う。bash のスクリプトは LF でないと動かないので、`.gitattributes` でファイルごとに決めている |
| .cmd ファイル（バッチファイル） | Windows のコマンドプロンプトで動くスクリプト。ダブルクリックでも実行できる。試作版の Windows 用の起動スクリプトが `scripts/dev.cmd` |

## Java・Gradle
| 用語 | 説明 |
|---|---|
| Gradle | Javaのビルドツール。ライブラリのダウンロード、コンパイル、テスト、jar作成をまとめて行う |
| Gradleラッパー（gradlew） | 決められたバージョンのGradleを自動で用意して実行するスクリプト。各自でGradleを入れなくてよい |
| マルチプロジェクト | 1つのリポジトリの中を複数のGradleプロジェクトに分ける構成（domain / infra / app） |
| 依存（dependency） | あるプログラムが使っている別のライブラリやプロジェクト |
| バージョンカタログ | `gradle/libs.versions.toml`。使うライブラリとバージョンを1か所にまとめたもの |
| record | 値を入れるだけのクラスを短く書けるJavaの書き方。作ったあとに中身を変えられない |
| アノテーション | `@` で始まる目印（例: `@Test`、`@SpringBootApplication`）。フレームワークがこれを見て動きを変える |
| JUnit | Javaのテストフレームワーク。`@Test` を付けたメソッドがテストとして実行される |
| AssertJ | テストで「期待どおりか」を `assertThat(実際).isEqualTo(期待)` のように読みやすく書くライブラリ |

## Spring Boot
| 用語 | 説明 |
|---|---|
| Spring Boot | Javaで業務アプリを作るためのフレームワーク。Webサーバーや設定の多くを自動で用意してくれる |
| Bean | Springが管理する部品（オブジェクト）。必要な場所へ自動で渡してくれる（DI: 依存性の注入） |
| オートコンフィグ | 依存ライブラリを見て、Springが自動で設定を行う仕組み |
| コントローラー | HTTPリクエストを受け取って処理を呼び出し、レスポンスを返すクラス |
| プロファイル | 起動時に選ぶ「設定の組み合わせ」の名前。`demo` プロファイルで起動したときだけサンプルデータを入れる、のように使い分ける |
| フィルター | リクエストがコントローラーに届く前に必ず通る関所。秘密キーの確認などに使う |
| 例外ハンドラー（@RestControllerAdvice） | 処理の途中で起きたエラー（例外）を、まとめてAPIのエラー応答に変換するクラス |
| Spring Security | Spring で「ログインしているか」「その操作をしてよいか」を確かめるためのライブラリ。リクエストがコントローラーに届く前に、フィルターでトークンを確かめる（`app/security/SecurityConfig.java`） |
| MockMvc | Webサーバーを立てずに、HTTPリクエストを送ったつもりでAPIをテストできる道具 |

## API・OpenAPI
| 用語 | 説明 |
|---|---|
| OpenAPI | APIの形（URL、送るデータ、返るデータ）を書くための標準の書式 |
| コード生成 | OpenAPI定義から、Javaのインターフェースや TypeScript の型を自動で作ること |
| HTTPメソッド | GET（取得）、POST（作成）、PATCH（一部更新）、PUT（置き換え）、DELETE（削除） |
| ステータスコード | APIの結果を表す数字。200 成功、201 作成成功、400 入力の誤り、401 未ログイン、403 権限なし、404 見つからない、409 競合 |
| 認証 / 認可 | 認証は「あなたは誰か」を確かめること（ログイン。失敗は401）。認可は「その人がその操作をしてよいか」を確かめること（失敗は403） |
| トークン / JWT | トークンはログインした証拠として受け取る文字列で、APIを呼ぶたびに `Authorization: Bearer トークン` ヘッダーに付けて送る。JWT はトークンの形式の1つで、「誰か・いつまで有効か」などの中身と、偽造を見抜くための署名が入っている |

## 画面（React・TypeScript）
| 用語 | 説明 |
|---|---|
| React | 画面を「コンポーネント」という部品の組み合わせで作るライブラリ |
| コンポーネント | 画面の部品。関数として書き、JSXで見た目を返す |
| JSX / TSX | JavaScript（TypeScript）の中にHTMLに似た書き方で画面を書く記法 |
| TypeScript | JavaScriptに型を足した言語 |
| Vite | 開発用サーバーとビルドのツール |
| npm | JavaScriptのライブラリを管理するツール。`package.json` に使うライブラリを書く |
| React Router | URLに応じて表示するページを切り替えるライブラリ（`/` は一覧、`/stream` は配信用画面など） |
| useState | コンポーネントが覚えておく値（状態）を作る仕組み。値を変えると画面が描き直される |
| useEffect | 画面を表示したあとに行う処理（APIからの読み込みなど）を書く場所 |
| プロキシ | 中継役。開発中は Vite が `/api/...` へのリクエストをバックエンド（8080）へ中継する |
| デザイントークン | 色や角の丸みなど、見た目の決まりに名前を付けた変数（例: `--color-navy`）。`frontend/src/index.css` の先頭にまとめ、画面では名前で使う。色を変えるときは1か所を変えればよい |
| コンテキスト（React） | 親のコンポーネントで用意した値を、間の部品を経由せずに子孫の部品から読める仕組み。ログインしている人の情報（`useAuth()`）に使っている |
| localStorage | ブラウザに文字を保存しておける場所。タブを閉じても消えず、同じサイトのほかのタブからも読める。ログインのトークンを入れている |
| ミドルウェア（openapi-fetch） | すべてのAPI呼び出しに共通でかける処理。トークンをヘッダーに付ける、401ならログイン画面へ移す、を `api/client.ts` に書いている |
| カスタムフック | `use` で始まる、コンポーネントで使い回す仕組みをまとめた関数。このツールでは確認のダイアログを出す `useConfirm` がある |
| `<dialog>` 要素 | ブラウザに備わっているダイアログの部品。`showModal()` で開くと、後ろの画面を押せなくする・Esc キーで閉じる、をブラウザがやってくれる |
| ドラッグ＆ドロップ（HTML） | ブラウザに備わっている「つまんで動かす」仕組み。一覧の並べ替えに使う（`draggable`、`onDragOver`、`onDrop`） |
| prefers-reduced-motion | OSで「動きを減らす」を設定しているかをCSSで調べる書き方。設定している人には画面の動きを止める |

## AWS
| 用語 | 説明 |
|---|---|
| AWS | Amazonのクラウドサービス |
| サーバーレス | サーバーを自分で用意・管理せず、使った分だけ動く仕組み。アクセスが少なければ費用もほぼかからない |
| Lambda | リクエストが来たときだけプログラムを動かすサービス。ここではSpring Bootアプリを動かす |
| SnapStart | Lambdaの起動を速くする仕組み。Javaは起動が遅いので使う |
| API Gateway | 外からのHTTPリクエストを受けてLambdaへ渡す入口 |
| DynamoDB | AWSのデータベース。表（テーブル）にキーと値で保存する。SQLは使わない |
| パーティションキー / ソートキー | DynamoDBでデータを探すためのキー。設計メモでは PK / SK と書く |
| GSI | DynamoDBの「別の並び順で探すための索引」 |
| 単一テーブル設計 | 応募・抽選記録・設定など種類の違うデータを、1つのテーブルにキーの付け方で分けて入れる、DynamoDBでよく使うやり方。このツールのテーブルは `Main` の1つだけ |
| DynamoDB Local | AWSの公式が配っている、自分のPCで動くDynamoDBの代わり。AWSのアカウントなしで試せる。テストと手元の動作確認に使う（ポート8000） |
| 条件付き書き込み | 「この条件のときだけ書く」とDynamoDBに頼む書き方。条件は書き込みと同時に確かめられるので、2人が同時に書いても片方だけが成功する |
| トランザクション | 複数の書き込みを「全部成功するか、全部やめるか」のどちらかにする仕組み |
| 強い整合性 / 結果整合性 | 強い整合性は、直前に書いた内容が必ず読める読み方。結果整合性は、書いた直後（1秒未満）はまだ古い内容が見えることがある読み方。DynamoDBのGSIからの読み込みは結果整合性になる |
| S3 / CloudFront | S3はファイル置き場、CloudFrontはそれを速く配信する仕組み。画面のファイルを置く |
| Cognito | ログインの仕組みを提供するサービス。運営・配信者・関係者をグループで分ける |
| CDK | AWSの構成をプログラム（ここではJava）で書いて作る仕組み |

## このツールの業務用語
| 用語 | 説明 |
|---|---|
| 重複 | 同じXのIDで、まだ終わっていない応募がすでにある状態 |
| 再応募 | 同じXのIDで、過去に終わった応募がある状態 |
| 印の付け直し | 同じ人のほかの応募のステータスやXのIDが変わったときに、重複・再応募の印を決め直すこと。例: 古い応募を見送りにすると、新しい応募の「重複」が「再応募」に変わる |
| 重複の解消 | 応募の詳細の「この応募を残す」。同じ人のほかの「未着手・分析予定」の応募を「見送り（再送のため）」にする。分析予定（当選を含む）は残す応募が引き継ぐ |
| 見送りの理由 | 見送りにするときに選ぶ理由。重複（再送のため）／条件外／本人の取り下げ／その他 |
| 役割 / 権限 | 役割は運営・配信者・関係者の3つ（仕様 3章）。権限は「応募の変更」「まとめ抽選」のような、できることの単位。どの役割がどの権限を持つかは `backend/domain` の `AccessPolicy` で決めている |
| 二段階認証（MFA） | パスワードに加えて、スマートフォンのアプリに出る数字なども入れてログインする方法。仕様 v1.1 では配信者と運営が使う決まりだったが、v1.2 でログインごとなくした |
| SQLite | 1つのファイルにデータを保存するデータベース。サーバーを別に動かさなくてよい。仕様 v1.2 で使う |
| jpackage / インストーラー | jpackage は、Java のプログラムを Java の実行環境ごとまとめて、Windows のインストーラー（ダブルクリックでPCに入れるファイル）にする道具。JDK に入っている |
| 127.0.0.1（ループバック） | 「このPC自身」を表す住所。ここでだけ待ち受けると、ほかのPCからはつながらない。`localhost` も同じ意味で使う |
| ウェブアプリ（Apps Script） | Apps Script を、URLで呼べる窓口として公開するしくみ。仕様 v1.2 では、ツールがここからフォームの回答を取りに行く |
| CSRF / DNSリバインディング | どちらも、ブラウザで開いたほかのWebサイトが、裏でこのPCのツールに命令を送ったりデータを読んだりする攻撃。ログインのないツールでは、届いた要求の Host・Origin ヘッダーを確かめて防ぐ |
| VACUUM INTO | SQLite の命令で、使用中のデータベースの中身を、別のファイルにそろった形で書き出す。バックアップに使う |
| 仮ログイン | 手元で試すときのログイン。試しユーザーを選ぶだけでログインできる（`app.auth.mode: dev` のときだけ使える）。仕様 v1.2 でログインをなくしたので、段階4で外す |
| 配信の操作の許可 | 配信者が、関係者ごとに「次の人へ」などの配信中の操作を手伝ってもらうための許可（初めは許可しない）。設定画面で変える |
| 版（同時変更の検知） | 応募ごとの番号で、保存するたびに1増える。画面で読み込んだときの版と今の版が違えば、ほかの人が先に変更したとわかるので保存しない（「楽観ロック」と呼ばれるやり方） |
| 変更履歴 | ステータスやXのIDを「いつ・誰が・何から何へ」変えたかの記録。応募の詳細の下に出る |
| 仕組みが行う変更 | 抽選・「次の人へ」・重複の解消のように、人が表から選ぶのではなくツールがステータスを変えること。「落選」はこれでだけ付く |
| 分析メモ・配信アーカイブURL | 分析済みにするときに残す要点と、配信の録画のURL。次に同じ人を分析するときに「前回の分析」として出る（管理画面だけ） |
| 落選補正 | 落選が続いた人ほど次の抽選で当たりやすくする仕組み。当選するとリセット |
| 乱数の種（seed） | 乱数の出発点になる数。同じ種なら同じ抽選結果になるので、後から結果を確かめられる |
| フォームの版 | フォームの質問項目のバージョン。項目が変わっても古い応募を正しく読むために記録する |
